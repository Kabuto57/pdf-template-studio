== THE RULES (exact meaning) ==
An answer's value, for rules: text/date/select = the text ("" if blank); radio = the option text or "" if none picked;
check = "true" or "false"; checks = the list of ticked option texts.
A rule is {"field": F, "values": [V1, V2, ...], "not": optional true}.
  - It holds when the answer of F is one of the values. For a "checks" answer: when any ticked option is one of the values.
  - With "not": true, it holds when F's answer is NOT one of the values AND F is answered (not blank).
    So {"field": F, "values": [""], "not": true} means "F is filled in".
"required": true            -> always mandatory.
"requiredIf": [rules]       -> mandatory when ANY of these rules holds.
"activeIf": [rules]         -> the question only applies when ANY of these rules holds; otherwise lock it.
If there is no "activeIf", the switching rules are the "requiredIf" rules that do NOT have "not": true.
  A question with no switching rules always applies.
A question that doesn't apply must be: read-only, fill colour grey (RGB 0.9, 0.9, 0.9), and its answer cleared
(text "", drop-down blank, nothing picked or ticked). When it applies again: editable, normal fill colour.
Mandatory and empty (and applies) -> border red (color.red) and fill light red (RGB 1, 0.9, 0.9).
Otherwise -> border back to its original colour (red if "required": true, grey otherwise), normal fill.
"max": N  -> at most N characters (also set the field's character limit).
"format":
  number  -> whole number: digits only. Message: "should be a whole number". Keys allowed while typing: 0-9.
  amount  -> ^\d{1,3}(,?\d{3})*(\.\d{1,2})?$ . Message: "is not an amount". Keys: 0-9 . ,
  phone   -> ^\+?[\d ()-]*\d[\d ()-]*$ . Message: "is not a phone number (digits, spaces, + - ( ) only)". Keys: 0-9 + ( ) space -
  account -> ^\d[\d-]*\d$ or a single digit. Message: "is not an account number (digits and - only)". Keys: 0-9 -
Every "text" and "long" answer: only these characters are allowed (SWIFT-safe):
  A-Z a-z 0-9 space . , - / ( ) ' : ? + # & @ % and line breaks.
  Message: "has characters the bank's SWIFT messages can't carry". Upper-case letters as they are typed.
Dates ("kind": "date"): DD/MM/YYYY, a real day for the month (no 31/04; 29/02 only in leap years).
  Message: "is not a real DD/MM/YYYY date". Use the Acrobat date format "dd/mm/yyyy" on these fields so
  Acrobat shows its calendar pop-up.
Checks across answers (only when both dates are real):
  - expiry_date before latest_shipment_date -> expiry_date "is before the latest shipment date"
  - latest_shipment_date before application_date -> latest_shipment_date "is before the application date"
  - expiry_date before application_date -> expiry_date "is before the application date"
  - application_date after today -> application_date "is in the future"
  - amount is a valid amount but not more than 0 -> amount "must be more than zero"
  - insurance_arrangement answered while price_basis is "CIF" or "CIP" ->
    insurance_arrangement "is only for FOB/CFR/FCA/CPT, but price basis is <price_basis> (the beneficiary insures)"
Messages are "<label> <message>", e.g. "Term: days is mandatory because Drafts at is "Term"".
  Missing: "is mandatory" (always) or "is mandatory because <rule in words>".
  Rule in words: '<label of F> is "<V>"' (or 'is ticked' / 'is not ticked' for "true"/"false"; 'is filled in' for the not-blank rule),
  several joined with " or ".
