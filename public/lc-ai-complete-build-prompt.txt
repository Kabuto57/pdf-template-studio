== PART 2: PROBLEMS WE ALREADY HIT (each one: what we saw, why, and the rule that prevents it) ==
P1. After the design was improved, all the checking was gone: no Check form / Reset form, red boxes stopped, the
    date was no longer a calendar.
    Why: the pages and fields were rebuilt, and rebuilding drops every script and action attached to them.
    Rule: R1. Scripts last; any rebuild means redoing all of PART 5.
P2. EVERY box was red, even questions that don't apply.
    Why: red borders and the Required flag were drawn into the file on every field, or a home-made script marked
    everything mandatory.
    Rule: no static red. Draw boxes with a normal black border; the colours are set ONLY by lcRules (PART 5.1),
    which makes a box red only while it is mandatory AND blank or wrong. Switched-off questions are grey.
P3. Conditional questions could not be clicked: after ticking "Drafts for 100% invoice value at", Sight / Term /
    Date stayed locked (but turned red).
    Why: (a) the PDF ReadOnly flag was set in the file, so the script's unlock didn't win; (b) the tick box had no
    Mouse Up action, so the rules didn't run when it was ticked; (c) the pick-one options' values were not the
    option texts (e.g. "Choice2" instead of "Term"), so the rule "Drafts at = Term" never matched.
    Rule: no ReadOnly flag in the file; Mouse Up lcRules(this) on every tick box and every option; every pick-one
    option's export value is EXACTLY its option text from the SPEC; a tick box counts as ticked when its value
    is anything but "Off".
P4. The calendar pop-up disappeared from the date boxes.
    Why: the upper-case / SWIFT typing filter was put on the date boxes (replacing the date Keystroke action), or
    the date Format action was missing, or the date box was a drop-down / comb / had a character limit.
    Rule: PART 5.3. Date boxes have ONLY the two AFDate actions + On Blur; plain one-line text, no character limit.
P5. "Check form" / "Reset form" / "Previous" / "Next" did nothing.
    Why (any of): they were only drawn shapes, not real push-buttons; the action was on the wrong object or event;
    something on top took the click (e.g. the hidden "__checks" field or a drawn rectangle); the button was hidden
    or read-only; lcRules was missing or had a different name; the script had an error (Acrobat fails silently).
    Rule: PART 5.4 and 5.5: real push-buttons, Mouse Up action on the widget, nothing on top, lcRules present once.
P6. Then the Check form / Reset form buttons were missing entirely.
    Why: a later fix rebuilt the header and dropped them.
    Rule: buttons are part of the one-pass package (PART 5.4) and are checked every time (PART 7).
P7. When the buttons were added back, Drafts and the other conditional questions broke again.
    Why: patch on patch: old and new scripts both in the file (duplicate document scripts, old helper fields,
    leftover actions, leftover ReadOnly flags), fighting each other.
    Rule: R3. One clean, complete set: exactly one document script "lcRules", one "__checks" helper, nothing old.
P8. After clicking Reset form, the buttons turned into solid black boxes (the caption vanished).
    Why: Acrobat redraws a button from its own settings on reset/click. The settings said black text (/DA "0 g")
    on a black background (/MK /BG), so the redraw was black on black.
    Rule: PART 5.4: /DA white ("1 g"), /MK black background and border with the caption, highlight not invert.
P9. Filled-in mandatory boxes turned black again but kept a thin red tint / outline.
    Why: that outline is Acrobat's own "required field" marking. It shows on every field whose Required flag is
    on, even when filled. The script used to leave the flag on after the box was answered.
    Rule: no Required flag in the file; lcRules turns it on only while a box is blank or wrong (already in 5.1).
P10. Reset form cleared the starting answers (e.g. Mode of advising "Full Swift").
    Why: the starting answers were only current values, not the fields' default values.
    Rule: PART 5.6: set them as default values (/DV) too.
P11. The script was corrupted when copied through email / chat: a field property written as "f", a dot and
     "name" became a web link.
    Why: mail and chat apps turn things that look like web addresses into links.
    Rule: the script is written with f["name"] to avoid this. Copy it exactly from this prompt; if your copy contains
    any link, "mailto:" or "http", it is corrupted: use the text exactly as shown here.
P12. A drop-down that should be blank counted as answered.
    Why: its "blank" entry was a space " " (not empty), or the first real option was pre-selected.
    Rule: drop-downs start with NO selection (value ""), unless PART 5.6 gives a starting answer.
P13. The form looked wrong: the order of questions was changed, labels were shortened, blue was used, and there
    were big blank gaps.
    Why: the layout was "optimised" by moving and rewording questions.
    Rule: PART 3. Keep the SPEC's order and wording exactly; black, white and grey only (red only for problems);
    no blank gaps.
P14. The QR box showed the JSON text instead of a QR code.
    Why: "__qr" was made as an ordinary text field (or the PDF library drew its value as text). Acrobat only draws a
    QR code for a barcode field: a text field carrying a /PMD (paper metadata) dictionary and /DataPrep 0, as
    Acrobat's own Prepare Form > Barcode tool makes. Without them Acrobat shows the text.
    Rule: PART 5.8 gives the exact field dictionary. Build "__qr" EMPTY (no value) and with NO text appearance; the
    code is drawn by Acrobat when Generate QR Code sets the value. Never put the JSON in the file yourself.
P15. After the QR code was added, ALL the buttons stopped working.
    Why: the new feature was patched on top: scripts re-written or duplicated, a script with an error (Acrobat then
    stops ALL document JavaScript silently), button actions lost when pages were rebuilt, or old buttons left over.
    Rule: R1 to R4. Build everything in one pass from this prompt; the QR script goes INSIDE the one document script
    (PART 5.1, after lcRules), so there is still exactly one document script; check it parses (PART 7).
P16. The QR code was tiny in its box, or changed size as answers changed.
    Why: Acrobat draws each module at a fixed size, so the code's size follows the length of the text.
    Rule: the text is padded to 2,300 characters (in lcPayload), and the module size is set so that one size of code
    fills the 450 pt box (PART 5.8).

== PART 4: FIELDS AND NAMES (Step A; the bank's systems read the filled PDF by these names, keep them exactly) ==
  - Each question is a form field named by its "id" in the SPEC.
  - "text" / "long" (multi-line) / "date": a text field <id>.
  - "select": a drop-down <id>. "radio": a pick-one group <id> whose option values are the option texts.
  - "check": a single tick box <id>.
  - "checks" (tick any): one tick box per option, named <id>__0, <id>__1, ... in the order of "options".

function val(id) {
  var m = M[id], f, a = [], i;
  if (m.kind == "checks") { for (i = 0; i < m.options.length; i++) { f = d.getField(id + "__" + i); if (f && f.value != "Off") a.push(m.options[i]); } return a; }
  if (m.kind == "date" && shown(id)) return d.getField(id).valueAsString;
  if (m.kind == "date" && d.getField(id + "__list")) { a = /^(\d\d) (\w{3}) (\d{4})$/.exec(d.getField(id + "__list").valueAsString);

  f = d.getField(id); if (!f) return "";

function empty(x) { return typeof x == "object" ? !x.length : x === ""; }

// Does any of these rules hold?
function any(rules) {
  var i, j, x, hit;
  for (i = 0; i < rules.length; i++) {
    x = val(rules[i][0]); hit = false;
    if (typeof x == "object") { for (j = 0; j < x.length; j++) if (has(rules[i][1], x[j])) hit = true; } else hit = has(rules[i][1], x);
    if (rules[i][2] ? !hit && !empty(x) : hit) return true;
  }
  return false;
}
function mandatory(id) { var m = M[id]; return m.always ? true : any(m.requiredIf || []); }

// What is wrong with a typed answer, or "".
function wrong(id) {
  var m = M[id], f = d.getField(id), s = m.kind == "date" ? val(id) : f ? f.valueAsString : "", x, k;
  if (!m.check || !s) return "";
  x = s.match(new RegExp("[^A-Za-z0-9 .,\\-/()':?+#&@%\\r\\n]", "g"));
  if (x) { k = []; for (var i = 0; i < x.length; i++) if (!has(k, x[i])) k.push(x[i]); return "remove " + k.join(" ") + " (letters, digits and . , - / ( ) ' : ? + # & @ % only)"; }
  if (m.kind == "date") { x = /^(\d\d)\/(\d\d)\/(\d{4})$/.exec(s); k = x && new Date(+x[3], x[2] - 1, +x[1]); return k && k.getDate() == +x[1] && k.getMonth() == x[2] - 1 ? "" : "not a real date (DD/MM/YYYY)"; }
